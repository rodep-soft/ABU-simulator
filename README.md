# ABU Robocon 2027 Strategy Simulator

新しいアプリは [field-simulator.html](field-simulator.html) です。HTMLをブラウザで開くだけで動きます。インストール、サーバー起動、インターネット接続は不要です。`sim/` と `vendor/` は同じフォルダー構成のまま必要です。

共有ZIPは「すべて展開」してから起動してください。[起動案内](00_START_HERE.txt) と [戦略追加ガイド](STRATEGY_GUIDE.md) を同梱しています。共有版は試合ログ・検証画像・作成者の環境専用のブラウザテストを除きます。各端末で独立して動き、端末間で対戦を同期する機能はありません。

## フィールド検証アプリ（2026-09-24）

- CADのmm座標をメートルへ変換した2Dフィールド。STLの座標から `x=(X-100)/1000`、`y=(11100-Y)/1000` と対応付け、2 mmの床板厚は接地高さの基準から除外。
- 4台が同じ時刻軸で動く180秒の基本動作。TRとBRの判断処理は独立。
- A*経路探索、車体外形、壁、階段・坂の出入口、物体、ロボット同士の干渉を検査。
- 坂は減速、階段は各段で停止。最高速度・加速度、速度倍率1 / 3/4 / 1/2 / 1/4を設定可能。
- TR最大3個、BR最大2個。全53個の物体を個体管理し、Earth/Skyの床置き受け渡し、Mustikaの直接受け渡し、積み上げ・反転・奉納を判定。
- BRは受け取り前後の見渡し停止を行い、通常は2個を一連の作業で配置する。終盤対応モードだけは150秒以降に単体運搬も比較する。走行中は盤面の観測を自動更新しない。
- 手動で移動や各操作を試せる。操作不可の理由と根拠、未確定事項を表示。
- 積載、受け渡し在庫、各タワーの段・色、得点内訳、条件達成時刻を表示。
- 一時停止、0.5秒送り、1 / 3 / 5 / 20 / 60倍速（初期値3倍）、3分計算、過去の軌跡再生、拡大縮小、JSONログ保存。再生倍率はロボット性能とは独立。

手動操作は動作検証用です。実競技でBRを手動操縦できるという意味ではありません。自動運転には固定手順と有限先読みの得点探索があり、180秒全体の最適性を保証するものではありません。

### L2見渡し・試合後の盤面検討

- PowerPointのスライド5に合わせ、L2の左右階段を上がった付近に赤・青の見渡し場所を追加。L2作業後は同じ階で1秒停止して認識します。補給・返却後は従来のL1で認識し、経路の階段時間も探索評価に含めます。
- 「3分計算」などで180秒まで終了したら「盤面検討」を選択。図上のタワー、または右側の各段のブロックを選び、赤・青の色ボタンで得点先を変更できます。選択した種類に応じて「Earth反転」「Sky反転」でもワンクリックで切り替えられます。Earth反転は試合後の検討専用です。
- 上部得点は検討中の仮想値、右側は元の試合結果・検討後・増減と赤青の点差を表示。取消・やり直し・全リセットに対応。「試合結果へ」やリプレイ移動で原試合へ戻り、再度検討を開くと編集を復元します。新規試合への初期化では検討を破棄します。
- 通常のログ保存は常に原試合。検討欄の保存は原盤面と仮想盤面を別形式で保存します。搬送点・Mustika点・条件達成履歴・終了時の接触による得点除外は固定し、過去の行動や合法な到達可能性は再シミュレーションしません。
- `sim/post-match-review.js` がコピー上の色変更と再集計、`sim/tests/l2-review.test.cjs` がルール・得点差・原試合保護のテストです。

### 戦略の選択

画面上部の「採用中の戦略」の変更ボタン、または「戦略」タブから、赤・青それぞれのTR搬送戦略とBR配置戦略を選べます。「この戦略で初期化」で適用します。選択途中は「変更あり・未適用」と表示され、実行中の戦略は変わりません。速度などの「設定」は別管理で、戦略を適用しても運動性能は維持されます。未適用の戦略変更は元に戻せます。

初期設定は赤・青ともTRが「効率化 · 必要量補給＋Mustika先回り」、BRが「効率化 · まとめ運搬＋Mustika最優先」です。初便E3・次便E1+S2から始める場合はTRの「効率化 · E3 → E1+S2＋必要量補給」を選びます。

従来のTR「基本補給 · E2+S1」「Earth先行 · E3 → E1+S2」、BR「得点探索 · 2往復先読み」「基本建設 · 専有→共有」「分散先置き · 共有1＋専有1」も比較用に残しています。

### 基本の2戦略モード

「戦略」タブの各チームの「戦略モード」でTRとBRの組み合わせを一度に選び、「この戦略で初期化」で適用します。赤青は独立して選択でき、従来の個別設定も残しています。

| モード | 150秒まで | 150秒以降 |
| --- | --- | --- |
| Mustika最速案 | 初便E3。共有・専有にEarthを1個ずつ分散。相手が完成させた共有塔は反転し、相手が置かなければ自力で2塔完成を目指す。取得条件達成後は奉納を優先し、その後は新規配置・専有を優先 | Sky配置・連続反転で点差を優先 |
| Earth固定点 → 終盤Sky | L2 Earth → L1専有Earth → L1共有Earthの優先順。Earthの候補がなくなれば新規Sky配置、その後に反転 | Sky配置・連続反転で点差を優先 |

- 2モードともTRは `stock-e3`。最初のE3だけは固定し、その後は在庫上限Earth3・Sky4へ不足分を補給します。BRが持つ同種の荷物の返却分は空けるため、床在庫を常に3/4個にするわけではありません。Mustikaは引き続き手渡しです。
- TRは空きのある種類を選んで納品できます。満杯・BR受取中は受け渡し停止位置を空け、同じ側の坂上で待機します。源泉の在庫不足や満杯なら待機は必要です。
- `efficient` と2モードは、空荷の反転を複数箇所まとめて計画できます。見渡し時の情報だけで対象と順番を確定し、途中に帰還・再認識を挟みません。相手に作業を成立させられなくされた場合は、従来どおり現地停止・再認識します。
- 操作欄に「現在の方針」と「作業予定」を表示します。切替は150秒以降の次の計画からで、進行中の作業を時間だけで取り消しません。
- 建設は2個の有用な配置を一組とし、積載上限はTR3・BR2のまま。複数反転できることと、同時に持てる数は別です。
- 優先順位は比較用の仮説で、勝率や数学的な最速を保証しません。新モードは現在の観測に対する1作業列を評価します。将来の相手の反応やTRの追加納品は先読みしません。

### 勝ち方を比較する追加3モード

同じ「戦略モード」から選択できます。3モードともTRは初便E3・以降Earth3/Sky4補給で、Mustikaの直接受取・奉納を優先する共通手順を維持します。初期選択は従来のままです。

| モード | BRの判断 |
| --- | --- |
| 2段目狙い · E1＋S1 | 既存Earth1段の上にEarth2段目とSkyを置く組を優先。L2の組を先に比較し、相手の土台利用は同得点時に優先。機会がなければ2段目・固定点の増える建設を行う。150秒以降はSky配置・連続反転 |
| 点差対応 · 専有／共有 | 最後の見渡しでリードしていれば専有の加点、次にEarthなどの固定点を優先。同点・追走中は時間あたりの点差改善を比較し、共有反転も候補。通常建設は2個 |
| 終盤対応 · 反転順序＋1個運搬 | 150秒未満はMustika最速案と同じ。150秒以降は単体運搬も含め、時間内の建設と連続反転の順番を比較。Sky再反転を試算してもリードする候補、試算前なら逆転可能な候補、それ以外の順。作業完了予測には1秒の余裕 |

追加した理想認識は、停止認識時の両チーム得点と相手BRの位置です。相手の最高速・操作時間は事前に既知と仮定し、相手の内部計画・未来位置を取得しません。走行中の観測は更新しません。実機で得点・相手位置を認識できるか、視野・遅延・誤差の検証は別途必要です。

終盤の相手は、直線移動・認識待ちなし・空手として速めに見積もります。複数Skyの再反転と終了時の接触による失点を比較しますが、相手の新規建設・運搬点・Mustika取得・妨害は予測しません。「Sky応答後の参考点差」は勝ち確定判定ではありません。反転順は単純な距離順や近い順に固定せず、各Skyを置く・反転する時刻と相手の到達時間で評価します。

操作欄の「選択の理由」に観測点差、単体運搬、終盤の参考点差を表示し、判断ログにも保存します。詳しい優先順位と編集場所は [戦略追加ガイド](STRATEGY_GUIDE.md) にあります。

追加3モードは146件の自動テストと、色・速度を入れ替えた60試合で動作確認しました。[検証記録と対戦結果](results/competitive-modes-2026-09-24/VERIFICATION.md) を参照してください。全構成の総当たりではなく、比較用の部分集合です。

効率化版は必要な通常ブロックの補給、短時間待機を挟むまとめ受取、点差・時間・有用な2個運搬を考慮した有限探索を使います。Mustika取得前にBRの手持ち整理を準備し、TRが受け渡し区画で保持したままBRが直接受け取り、見渡し後に優先して奉納します。Earth/Skyの在庫列はMustika用に空ける必要がありません。条件達成前の取得や、BRの観測外での盤面更新は認めません。

### 返却・現地再計画の更新

- 受け渡し置場はEarth専用3個・Sky専用4個。BRは置けないブロックを返却でき、返却で運搬点を重複加算しません。TRはBRの手持ち分の返却場所を残します。空なら初便E3を全数納品できます。
- 初期選択のBR `efficient` は、通常の建設で「2個とも配置できる計画」を持って出発します。1個だけの通常出発は時間切れ直前でも行いません。Mustika単独、空手の反転、出発済みの作業失敗後の現地復旧は例外です。比較用の旧戦略は従来動作を維持します。
- 配置・反転に失敗したら、その場で停止して再認識します。残りの荷物で近くの別スポットへ配置できるか、TransferAreaへ返すかを比較します。通常の作業終了後は見渡し場所へ戻ります。
- 見渡し停止の初期値は1秒。現地認識も同じ時間を消費し、移動中に盤面を更新しません。
- サンクチュアリは2塔同時完成（うち共有1塔以上）の達成時刻と対象タワーを保存。「状態」欄に根拠を表示します。共有1塔だけでは未達ですが、過去に達成済みならその後反転されても有効です。
- 設定・戦略の適用とリセットで経路キャッシュを消去し、古い一括計算を無効化します。描画は最大20回/秒、競技計算の刻みは従来どおり0.05秒です。

前版（在庫E2/S2）の検証は [2026-09-23の検証記録](results/return-replan-verified-2026-09-23/VERIFICATION.md) に保存しています。今回の2モードの条件・判断・3分間の履歴は [2026-09-24の検証記録](results/two-modes-verified-2026-09-24/VERIFICATION.md) にまとめています。

従来の開幕固定版では1便目にEarthを3個、2便目にEarthを1個・Skyを2個集めて納品します。全数を納品してから次の便に進み、受け渡し区画が満杯の場合はその便の残りを保持して待ちます。指定された供給元が取得できない場合は、不足したまま出発せず再試行します。3便目以降は従来のE2+S1に戻り、サンクチュアリ条件達成後は取得可能なMustikaを優先します。効率化版のE3開幕では、その後を必要量補給へ切り替え、Mustikaへの移行を開幕指定より優先します。

便数はTR自身の納品履歴で管理するため、自動運転の停止・再開で初手に戻りません。手動で途中納品した場合は、その実際の積荷が1便として記録されます。TR戦略の変更は搬送内容のみを変え、BR戦略は独立して選択します。操作画面の「今回の搬送目標」「納品済み」、ログの「納品完了」で確認できます。設定と便ごとのブロックID・種類・完了時刻はJSONにも保存されます。

### BR: 従来の得点探索

見渡し場所で停止・認識した時点の盤面と受け渡し在庫、自分の手持ち、残り時間、移動性能を使って、最大2往復の候補を比較します。TRの将来の納品や相手の未来の行動は予測しません。現在の理想観測には味方の位置・手持ちとMustika受渡待ちを含みますが、移動中には更新せず、内部計画・到着予定時刻は共有しません。以下は比較用に残した `score-search` の評価方法です。

- 在庫の上段から取り出せる0〜2個の組み合わせ、各専有・共有スポットへの配置、相手色Skyの反転、自分が置いた最上段Earthの回収、条件達成後のMustika奉納を列挙します。ルール判定と採点は実行エンジンの処理を再利用します。
- 1回の作業は手持ち数（空荷なら1回）まで、最大2操作。回収後は再認識が必要なのでその往復を終了します。受け取ったら一度見渡し場所で停止し、更新した情報から作業を再計画します。出発後の作業先は固定し、失敗時は帰還・再認識します。
- 経路の加減速、坂の減速、段差停止、受取・配置・反転・回収・奉納・見渡し時間を見積もり、終了までに完了する候補だけを比較します。速度倍率は最高速度と加速度の両方に反映します。
- 評価の第1優先は最大2往復での自チームの正味加点。同点ならサンクチュアリ条件の新規達成、短い所要時間、相手の加点が少ない順です。条件達成だけで250点を仮加算せず、実際に観測したMustikaを奉納できる場合だけ250点とします。
- 最初の回収で一時的に減点しても、次の往復でより高い段へ置いて正味加点できれば選択できます。Mustika奉納後も180秒まで他の加点行動を探します。
- 等価な盤面・在庫・手持ちに到達する経路は、作業完了時間と帰還・認識までの時間の両方で遅いものだけを除外します。上位N件だけ残すビーム探索やランダム抽選はしません。ただし探索深さ自体は最大2往復に限定しています。

**探索の限界:** 各スポットの代表作業位置1か所を使い、建設予定地は空でも障害物として予約して保守的に経路計算します。全移動経路の最短時間探索、相手の反応の分岐、将来の追加納品、勝率・確率的な期待値は扱いません。所要時間の予測はロボット同士の待ち時間を含まないため、競合や盤面変化があると実績は変わります。実際の移動では従来通り衝突を防ぎ、迂回を試みます。したがって「3分全体で必ず最大得点」や勝利保証ではありません。

BRを選択した操作画面に、選んだ作業・今回の予測加点・計画全体の予測を表示します。旧得点探索は最大2往復、2つの新モードは1回の出動または連続反転が対象です。「ログ」と保存JSONにも判断時刻、選択作業、予測点、予測時間、比較候補数を記録し、リプレイではその時点の判断を表示します。

### BR: 分散先置き

「戦略」タブのBR配置戦略で「分散先置き · 共有1＋専有1」を選びます。TRの「Earth先行 · E3 → E1+S2」と組み合わせられますが、BRを選んでもTRの設定は自動では変わりません。

- 赤はL1共有下と赤L1下、青はL1共有上と青L1下を初期の2か所にします。両方空なら取り出せるEarth2個を待ち、共有→専有へ各1個を同じ認識・配置計画で置きます。すでに土台がある場所には重ねて先置きせず、まだ空の側を優先します。
- 3個目のEarthは専有側の2段目に使用します。共有側は1段のまま残し、Earth単独では2段目を置きに行きません。
- 共有がEarth1段ならE1+S1を受け取って自力完成、Earth2段ならS1だけで完成します。相手色のSkyで完成していれば、空荷での次の出発では補給より反転を優先します。反転でEarthの得点帰属は変えません。
- 受け渡し在庫は実際に取り出せる上段から最大2個の候補を列挙します。S→Eの順に受け取っても配置はE→Sの順にできます。選別は固定優先順位で、勝率の全探索ではありません。
- 受け取り前後に見渡し場所で停止し、出発前に最大2操作を決定します。走行中に新しい盤面を読むことはありません。相手が途中で配置を変えて作業不能になったら、残りの予定を取り消して帰還・再認識します。2個保持中は反転せず、配置して空きを作るか、帰還後に改めて計画します。
- 2か所が自色で完成した後も、他のスポットの建設・反転やMustika奉納を続けます。競技は180秒で終了し、条件達成や奉納では終了しません。

共有への誘いに相手が応じる保証や、反転後の色を維持できる保証はありません。この実装は戦術比較用の1つの方針で、最強戦略の判定ではありません。

戦略を追加するときは `sim/controllers.js` の `catalog` にID・表示名・判断関数 `run` を登録します。TRの既存搬送動作を使う場合は `opening` と `repeat`、BRは表示用の `details(team)` も定義します。選択メニューはこの一覧から自動生成し、実行時も同じ登録情報から判断関数を選びます。競技の禁止事項・容量・認識制約は引き続きエンジン側で検査します。登録の変更はコード上で行う構成で、画面内の戦略作成エディターはまだありません。

### BRの行き詰まり時の自動Retry

自動運転中のBRが移動を阻まれ、位置の進展がない状態が試合内時間で5秒続いたら、自チームのL1 Retryエリアから再開します。5秒の停止時間に加えて別のリトライ待ち時間は課しません。一度もL1へ完全上陸していないBRは、活動域を飛び越えないよう地上の開始枠へ戻します。TR・手動停止は対象外です。

- 1秒ごとの迂回再計算や衝突回避の待機で、行き詰まりの5秒計時をリセットしません。1 cm以上の実移動で計時を解除します。通常の見渡し・把持・配置・段差停止・戦略的待機は行き詰まりに数えません。
- Earth/Skyは保持したまま再開します。これはユーザー確認済みのシミュレーション上の指定で、OPEN-01の公式解釈を確定するものではありません。保持中のMustikaは初期の柱へ戻します。配置済みのタワーや得点、達成済み条件は消去しません。
- 再開位置を他のロボットや物体が塞いでいる場合は空くまで待ち、重ねて配置しません。この待機中は元の移動や戦略判断を実行せず、荷物の状態も確定前に変更しません。
- 元の作業予定と観測を破棄し、Retry後は見渡し場所へ移動・停止・再認識してから、選択した戦略で再計画します。自動運転を解除した場合は自動Retryも取り消します。
- 状態欄に残り秒数やRetry待機・完了を表示し、要求・待機・再開位置・保持物をログとリプレイへ記録します。試合終了後には再開しません。

### 残る簡略化

車体は500 mm角の軸平行な外形、アームは幅80 mmの作業範囲として近似します。積載は車体上の縦積みを仮定し、転倒・摩擦・落下・細かい把持姿勢は剛体物理として再現していません。受け渡し区画はEarth専用3段・Sky専用4段、計7個を上限とするユーザー指定の仮モデルです。取り出しは各列の上からで、実機の把持高さや積み替え時間の追加は未モデル化です。

見渡しは停止完了時の理想認識で、遮蔽や認識誤差は未実装です。TRは停止時に公開盤面を確認できる操縦者を近似し、BRとの通信には使いません。TRの視覚・操縦者の死角は未モデル化です。故意の妨害、失格、最終審判裁定は自動判定しません。

衝突回避はシミュレーター側の理想的な近接検出です。双方が同時に迂回を繰り返さないよう、再経路計算時に片方は2秒待機します。待機する側は試合時刻10秒ごとに交代します。この待機は得点探索の所要時間予測には含まれません。

Earth/Skyの直接手渡し、Mustika混載、Earth/Skyを保持した手動リトライ、規定外の積み方、奉納済みMustikaの奪取は未対応として扱います。公式に禁止される操作とは区別しています。Mustika直接受渡と自動Retry時の荷物保持はユーザー指定として明記しています。
